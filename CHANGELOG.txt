APECSOUND - RELEASE NOTES
=========================

1.0.5
-----

VoiceOver support, live coding, host transport, XY pads, Monitor, and a
smarter import of Cabbage and CsoundQt files. No change to the .csd
format: files saved by 1.0.4 load unchanged.

ACCESSIBILITY - VOICEOVER

  apeCsound can now be used with VoiceOver on macOS and iOS (and with
  other screen readers that use the system accessibility API). Every
  control has a name, a role and, where useful, a description; the whole
  interface can be driven from the keyboard. In detail:

  * Toolbar and panels: Apply, Pause, the file capsule, Find, Main menu,
    Parameters menu, Snapshots, Evaluate line and Clear console are
    announced by name; the file capsule is a real button (Tab,
    Return/Space, VoiceOver "press"); the focus order follows the layout
    left-to-right, top-to-bottom.
  * Menus: the file menu, the main menu, the "+" menu and the "..." menu
    of every card are real menus for VoiceOver. Each entry is announced
    with its state (checked, disabled, submenu) and can be activated; when
    a menu opens the focus is already on the first entry, so it is read at
    once. Keyboard: Up/Down or Tab move, Return activates, Right opens a
    submenu, Left/Esc go back or close; the focus returns to where it was.
  * Code editor: an accessible text area. VoiceOver reads it by character,
    word and line, follows the caret and the selection, and typing,
    selecting and replacing text through the screen reader work like in a
    native text view. The help bar announces the help of the opcode under
    the caret.
  * Parameter cards: sliders, toggles and menus carry the channel name
    ("amp", "amp value"), the Edit and "..." buttons say which channel
    they act on ("Edit amp", "amp menu"), and the fields of the Edit card
    (channel name, Min, Max, Init, Skew, Step, options) are named.
  * XY pad: an accessible control that announces both axes with their
    channel names and values ("X cutoff 0.42, Y res 0.8"). VoiceOver
    increment/decrement moves X; from the keyboard the arrow keys move X
    (left/right) and Y (up/down), Shift for larger steps, Home/End and
    PageUp/PageDown jump to the ends; the pad shows a focus ring.
  * Nothing changes for mouse and touch users: no extra focus rings or
    highlighted menu rows appear unless the keyboard is used.

LIVE CODING

  * Evaluate: Shift+Return (or the right-click menu) sends the selection,
    the instr/opcode block around the caret or the current line to the
    running engine without a full recompile. Orchestra code is merged (an
    existing instr is redefined, notes already playing finish with the old
    version; global code runs at once), lines that start with a score
    statement are sent as real-time events. The sent lines flash.
  * Evaluate line: the help bar turns into an input line (round ">_"
    button at the top right of the console, above the trash button, or
    Cmd+E) for one-liners such as "i 3 0 1" or
    "gkfb = 0.9", with history (Up/Down); Esc goes back to the help bar.
  * Nothing evaluated is saved: at the next Apply only the editor text
    counts (the file stays the reference).
  * Right-click on the help bar: "Copy error" (or "Copy help") puts the
    text shown in the bar on the clipboard.

HOST AND ENGINE

  * Host transport as control channels, same names as Cabbage: HOST_BPM,
    IS_PLAYING, IS_RECORDING, TIME_IN_SECONDS, TIME_IN_SAMPLES,
    HOST_PPQ_POS, HOST_PPQ_BAR_START, TIME_SIG_NUM, TIME_SIG_DENOM -
    updated once per block, no allocation in the audio thread. Standalone:
    HOST_BPM = 120, 4/4.
  * Console warning when the code uses fixed-width I/O opcodes (outs, ins,
    out, outq...) and the track has a different channel count: prefer
    outch / inch, which work with any nchnls.

PARAMETERS PANEL

  * XY pad: "; @xy "X" "Y"" in the code shows two Float parameters as one
    two-dimensional pad card (drag, double-click to reset, both still
    separate DAW parameters). Edit shows both channel fields plus the
    range of one axis (Edit X / Edit Y in the "..." menu). Cabbage xypad
    widgets and CsoundQt XY controllers become pads automatically.
  * Monitor: channels written by chnset that are not parameters appear
    read-only in a "Monitor" group at the bottom of the panel - value and
    bar (range from chn_k hints, or the values seen so far), text for
    string channels. The equivalent of CsoundQt / Cabbage meters, displays
    and labels; channels created at run time appear within a second.
  * Cabbage files get their groups from groupbox / plant containers of the
    GUI, no change to the file needed; "; @group" in the code still wins.
  * More than 4 groups: only the first starts open when a file is loaded;
    the open/closed state is kept while the set of groups does not change.
  * Compact cards: the channel name sits in the title row (no more
    "SLIDER FLOAT" label); toggles and menus are single-line cards; one
    card in edit mode at a time, outlined in the colour of its type.
  * Per-card "..." menu: Copy chnget line, Reset to Init Value, Randomize,
    Show in Code (selects the chnget in the editor), Remove (with
    confirmation). The edit button shows a pencil, and a check mark
    (apply) while the card is in edit mode. "Randomize All" in the "+"
    menu.
  * Live preview: while editing a Float/Int slider the real slider stays
    visible under the name field and follows Min/Max/Init/Skew/Step as
    you type.
  * Inline validation of min/max/init/skew/step, options and duplicate
    channel names.
  * Code <-> panel link: with the caret on a chnget/chnset line the card
    of that channel flashes briefly.
  * A dot flashes next to the name when a value is changed from outside
    (DAW automation, chnset, snapshot recall).

IMPORT OF CABBAGE AND CSOUNDQT FILES

  * Cabbage import: one channel = one parameter (a channel used by two
    widgets, e.g. an rslider and an xypad, no longer gives duplicated
    cards).
  * Examples: the CsoundQt files now use chnget / chnset instead of
    invalue / outvalue (their displays and meters show up in Monitor);
    every example uses inch / outch; new tests in CSD/Examples/Test
    (EvaluateTest, HostTransportTest, XYPadTest, MonitorTest).

DEVELOPMENT

  * Unit tests (juce::UnitTest, Source/Tests/CsoundUnitTests.cpp): parameter
    groups / XY pads parser, Cabbage widget helpers, card field wrapping,
    Csound 7 functional syntax, channel-under-caret, Cabbage and CsoundQt
    import, parameter snapshots. Run them from Main menu > Config > Run
    Self-Tests (Debug builds only, result in the console), with
    "apeCsound --run-tests" (Standalone) or outside the app with
    scripts/run_unit_tests.sh (the pure suites, juce_core only). The pure helpers now live in
    CsoundCabbageHelpers.h, CsoundLayoutHelpers.h, CsoundSyntaxHelpers.h.

FIXES

  * Cabbage import: "button" widgets were not imported at all (only
    "checkbox"), so Play/Stop/Live/Rec buttons of many examples stayed at 0
    and the patch seemed silent; they are now Bool parameters.
  * Cabbage import: combobox value(n) is 1-based in Cabbage; the default
    menu entry was off by one (the next item was selected).
  * Console: error, warning and "deactivated" lines are never hidden by
    the flood filter (a macro expanded 16 times could bury an INIT ERROR).

  * After Apply the parameter channels could stay at 0 (sliders and menus
    looked reset, chnget returned 0 until the control was touched): the
    new engine was mistaken for the old one when it got the same memory
    address; engines are now told apart by a generation counter.
  * The "changed from outside" dot no longer flashes when hovering or
    clicking a toggle.
  * Field rows of the edit card: the last field could disappear at some
    panel widths; the fields now also stretch to the card width.
  * Leaving edit mode no longer shows the old "SLIDER FLOAT" label.
  * Snapshot/Parameter rebuilds no longer need a second click to leave
    edit mode while a field has focus.

1.0.4
-----

Built on Csound 7.0.0, the official release (tag 7.0.0, 21 October 2026). The
previous builds used a develop snapshot; every platform now builds from the
same tagged sources.

ENGINE

  * Csound 7.0.0 linked statically on macOS, iOS, Windows and Linux.
  * OSC opcodes built in (oscinit, osclisten, oscsend, oscbundle, oscraw;
    the uppercase names still work as aliases): liblo and the OSC plugin
    are compiled into the binary and registered on every engine instance.
  * NSLocalNetworkUsageDescription on iOS and macOS: the local-network
    permission for OSC is requested with a proper message.
  * Pause button next to Apply: stops Csound and passes the audio through;
    Apply restarts it.
  * Audio scaling fixed: the output and input are scaled by 0dbfs; a .csd
    with 0dbfs = 32767 is no longer 32767 times too loud.
  * Two-way channels: chnset on a mapped channel moves the parameter
    (slider, host, automation) instead of being overwritten every block.
  * Parameter names and ranges are refreshed in the DAW after Load.
  * Console flood protection: identical messages repeated more than three
    times per second are summarised; the console no longer freezes the
    DAW.
  * Warning in the console when a parameter channel is also used as an
    audio channel (chnget/chnset with a variables), which Csound rejects.

PLUG-IN TYPE

  * The AU / AUv3 is now a Music Effect (aumf): an audio effect that also
    receives MIDI. VST3 stays Fx. One plug-in for every use: to play a
    .csd instrument, load apeCsound as an effect and send it MIDI (the
    Guide explains how in Logic, Ableton Live, Cubase, REAPER, Bitwig,
    Studio One and the iOS hosts). Logic also lists it in the instrument
    slot under "AU MIDI-controlled Effects".

PARAMETERS PANEL

  * Groups: a ; @group Name comment in the code puts the parameters read
    below it - sliders, toggles and menus alike - under one collapsible
    frame; the group of a channel is where its first chnget is; parameters
    without a group go to "Other". Expand All / Collapse All in the +
    menu.
  * Snapshots (camera button on the right of the title bar): named sets of
    parameter values stored in the .csd and in the DAW project. Save,
    Recall, Overwrite, Rename, Delete; saving/renaming/deleting can be
    undone.
  * Larger sliders, with a touch-friendly thumb; on touch screens a
    horizontal drag moves the slider and a vertical one scrolls the panel.
  * Min/max labels shown as floats.

EDITOR

  * Graphs panel docked at the bottom, next to the console: function
    tables and display / dispfft signals drawn in the plug-in instead of
    ASCII graphs in the console; displays always on.
  * Find / Replace bar (magnifier button): match case, whole word, Replace
    / Replace All; Esc closes it.
  * Keyboard shortcuts, the same in the plug-in and in the standalone app:
    Cmd+Return Apply, Cmd+S / Cmd+Shift+S / Cmd+O / Cmd+N, Cmd+F,
    Cmd+1/2/3 panels, Cmd+= / Cmd+-, Cmd+Z / Cmd+Shift+Z, Cmd+/ comment,
    Ctrl+I re-indent, Cmd+[ / ].
  * Undo / Redo move the caret and the selection to the edited text and
    scroll it into view.
  * Block comments /* ... */ keep their colour after edits and scrolling.
  * apeCsound Guide rewritten: full-screen, laid out in sections with
    proper lists; scrolls with wheel, trackpad and finger.
  * The console scrolls with the finger on iOS.

FILES AND SESSIONS

  * Factory examples built into the binary and extracted to CSD/Examples
    on first launch (Cabbage and CsoundQt collections with credits and
    licences in README_Examples.md, plus ape/ and Test/). Open Example...
    and Restore Examples in the file menu.
  * Sessions live in ~/Documents/apeCsound/CSD: CSD/User is the default
    for Save as, CSD/Examples holds the examples.
  * Import Files... on every platform: the dialog shows only the supported
    types and copies each file to the right folder (.csd to CSD/User,
    audio to SSDIR, .udo/.inc/.txt to INCDIR, analysis files to SADIR).
  * Manage Files...: on desktop opens the apeCsound folder in Finder /
    Explorer; on iOS a file manager over the shared folder (import into a
    folder, export to the Files app, delete).
  * iOS file browser for Load / Open Example / Save as, presented like the
    system sheet: the shared App Group folder is not visible in the Files
    app, so apeCsound shows it itself; "Other Locations..." opens the
    system picker.
  * Config > Extra Folders (was "Csound Folders") on every platform: extra
    SSDIR / SADIR / INCDIR folders and the SFDIR output folder; on iOS
    chosen with the system picker and shared by the app and the AUv3.
  * .csd files associated with apeCsound on macOS and iOS (double click /
    Open in).
  * File menu reorganised in groups: Init, Load / Open Example, Save /
    Save as / Reveal in Finder, Import / Manage Files, Restore Examples.

MENUS AND UI

  * Touch-friendly menus on iOS and Android only; desktop keeps the
    native-style popup. Icons on every platform, keyboard shortcuts shown
    on desktop only; wider gap between icon and text.
  * Config menu: Modern Syntax in Help, Follow CSD nchnls, Light Editor,
    Extra Folders.
  * About: engine build line and credits for the examples.

BUILD AND DISTRIBUTION

  * Static Csound build scripts for macOS (universal), iOS (device +
    simulator), Linux and Windows, all pinned to the 7.0.0 tag; the OSC
    plugin is patched to build statically.
  * GitHub Actions for Windows and Linux: VST3 + Standalone, zipped.
  * README rewritten: formats per platform, download links, features,
    build steps.
