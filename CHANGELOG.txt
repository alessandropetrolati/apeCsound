APECSOUND - RELEASE NOTES
=========================

1.0.7 (October 2026)
--------------------

Buttons that start instruments (Toggle / Momentary, EVENT ON / OFF), a
Monitor without attributes where every kind of card has its own look,
Jump to Definition in the code editor, and a layout that is remembered.
(There is no 1.0.6: the number was skipped.)

BREAKING CHANGES

  * Monitor: the chn_k attributes of 1.0.5 are no longer read. Only
    "spark" is left. What changes in a patch written for 1.0.5:
      - "db"      the channel is shown as a plain number on an adaptive
                  track, no longer in dB. For a level meter write the
                  audio itself: chnset asig, "Level" (meter in dB).
      - "int"     no longer needed: whole numbers are shown without
                  decimals by themselves (round fractional values in the
                  code: chnset round(k)).
      - "hidden"  the channel is shown. To keep it out of the Monitor,
                  don't write it.
      - "group:"  channels are no longer joined by attribute: give them
                  the same prefix and an index (PeakL/PeakR -> Peak1/Peak2,
                  or a stereo pair Peak_L/Peak_R).
    Patches still load and run unchanged: Csound itself ignores the
    attributes, only the look of their Monitor cards changes.
  * "Toggle" parameters are now called Button. Nothing changes in the
    .csd: they are the same 64 Bool slots and load as before.

BUTTONS

  * A Button has a MODE: Toggle (a switch, as before) or Momentary - on
    while held, off when released. The DAW records press and release and
    plays them back. Momentary buttons are not randomized and not stored
    in snapshots (they would come back "pressed").
  * EVENT ON / EVENT OFF (optional, like a CsoundQt event button): score
    lines sent when the button goes from 0 to 1 (press, switch on, DAW
    automation) and from 1 to 0 (release, switch off), once per edge.
    With a held note - ON "i 10.1 0 -1", OFF "i -10.1 0 0" - the button
    plays like a key. Run by a small instrument apeCsound adds to the
    running engine (not to the .csd), updated as you type. Buttons with
    EVENT lines are not randomized.
  * Copy Trigger Code (card menu ...): the other way, as in Cabbage - the
    lines that start an instrument once per press from your own code
    (trigger + event), visible and portable.
  * New configuration: MODE (Toggle | Momentary) and INIT (Off | On) as
    segmented controls - one tap, touch friendly; INIT is disabled in
    Momentary but keeps its value. EVENT ON and EVENT OFF below, full
    width, with examples as placeholder text.

MONITOR

  * No attributes to learn: the look of a card comes from the channel
    itself - its type, its chn_k range, its values, its name - and each
    kind has its own look and icon:
      level bar with a ruler      range declared with chn_k
      ring on a dashed track      no range: between the min/max seen
      half-moon dial, needle      range through zero (LFO, pan)
      row of cells                whole numbers in a whole range of 3..33
                                  values (the position of a sequencer)
      glowing lamp, ON/OFF        a channel that only takes 0 and 1
      LCD-like display            strings (format them with sprintfk)
      filled curve                chn_k attribute "spark"
      segmented meter in dB       audio channels (chnset asig), with peak
                                  hold and a CLIP lamp
  * Multi cards by name: Base1, Base2... and stereo pairs Out_L/Out_R,
    OutL/OutR, MixLeft/MixRight; audio channels get vertical meters,
    0/1 channels a row of lamps.
  * CLIP: lights when a sample reaches 0 dBFS and stays on until the card
    is clicked. The audio thread keeps the sample peak of up to 16
    monitored audio channels (a few comparisons per ksmps, no locks).
    Meters follow 0dbfs.
  * Reading a card: hover for what it is and why it looks like that;
    right-click (long press on iOS) for "Copy chn_k Declaration" (a ready
    chn_k line with the range seen so far) and "Reset Observed Range"
    (also double-click).
  * "No change since Apply": a card whose channel never changes is dimmed
    and says so - usually a channel the code creates but never writes.
  * Compact mode (button in the Monitor header, or Parameters menu >
    Compact Monitor): one line per card, dozens of channels on screen.
  * Cards written below a "; @group Name" line sit in that group, next to
    the parameters; the Monitor group has its own grey colour.
  * Only the cards on screen are redrawn.

EDITOR

  * Jump to Definition, like Xcode: Cmd+click a name (Ctrl+click on
    Windows/Linux). A local variable goes to the first line that writes
    it in its instr/opcode, a global to its first assignment, a UDO to its
    opcode line, an instrument (event, schedule, scoreline, score lines)
    to its instr, a macro to its #define, a channel to its chn_k (or first
    chnget/chnset), a label to its line. With Cmd held the name under the
    mouse is underlined.
  * Go Back: the "Back to line N" button at the top right after a jump
    (it hides itself after a few seconds, a click, an edit or Esc), or
    Cmd+Option+Left (also Ctrl+Cmd+Left, Ctrl+-; Alt+Left on Windows and
    Linux). Jump from the caret: Ctrl+Cmd+J (Alt+J). Both are also in the
    right-click menu and, on touch, in the edit menu of a selected name.
  * Evaluate (>_) and Clear console sit side by side at the right end of
    the help bar.

LAYOUT

  * Each instance remembers its layout in the plug-in state (DAW project,
    standalone app on quit): window size (not on iOS), open panels
    (Parameters, Console, Graphs), panel widths, console height, closed
    groups, Monitor closed/compact, and the position in the code (scroll
    and caret). Not in the .csd; it never marks the session as modified.
  * A new instance starts from the last layout used. Config > Reset Layout
    restores the factory layout.
  * Channels (every engine channel, with Map and Unmap) opens as a window
    over the editor; its entry moved to the Parameters menu (+) as
    "Channels...", still Cmd+4.
  * Parameters title on the left; the + menu button on the right, next to
    Snapshots, in line with the Find button of the toolbar.
  * Main menu: apeCsound Guide has its own icon; About is set apart.

IMPORT (CABBAGE AND CSOUNDQT)

  * Cabbage buttons with latched(0) and CsoundQt value buttons without
    latch become Momentary buttons (they were switches that stayed on).
  * CsoundQt latch is read from <latch> (the mode), not from <latched>
    (the saved state, now the INIT of a Toggle): latched buttons no longer
    start "on" by mistake.
  * CsoundQt event buttons become Buttons with their score line as EVENT
    ON - Momentary, or Toggle with latch - and, for a held note (negative
    duration), an EVENT OFF that stops it as CsoundQt does ("i 11.1 0 -1"
    -> "i -11.1 0 -1", named instruments too). They are named after their
    text ("Bell") instead of the generated objectName ("b3682"). The code
    is not changed.

FIXES

  * Done on a new parameter now leaves edit mode (the click was lost when
    the name was confirmed by that same click).
  * Typing the name of a new parameter no longer leaves "a", "ap"... as
    stray channels in the Monitor and in Channels.
  * A momentary press no longer flashes the "moved from outside" dot.
  * New groups no longer reset the Monitor closed / compact state.

GUIDE

  * Contents list: a sidebar on wide windows (the current section is
    highlighted), a Contents button on narrow windows and iPhone; code
    examples as code blocks; shorter sections.
  * New sections: Buttons, Starting instruments with a button, Monitor
    (kinds of cards, reading a card), Jump to Definition, Layout and
    settings, Accessibility.

EXAMPLES (installed on first launch; a copy you modified is kept)

  * Test/ButtonTest.csd (new): every way to use a Button, one group each -
    Toggle (INIT Off / On), Momentary, EVENT lines (a bell, a held-note
    pad), events from the code (a chord, an arpeggio started and stopped).
  * Test/CsoundQtButtons.csd (new): a CsoundQt file with every kind of
    CsoundQt button, to check the import.
  * Test/MonitorTest.csd rewritten: one card per kind, explained, with a
    "try this" list. Test/MonitorStressTest.csd without attributes but
    spark.

1.0.5
-----

VoiceOver support, live coding, a Channels diagnostic panel, host
transport, XY pads, Monitor and live tables, unit tests, and a smarter
import of Cabbage and CsoundQt files. 64 toggle parameters. No change to
the .csd format: files saved by 1.0.4 load unchanged (see the note on
AU parameter indices under HOST AND ENGINE).

ACCESSIBILITY - VOICEOVER

  apeCsound can now be used with VoiceOver on macOS and iOS (and with
  other screen readers that use the system accessibility API). Every
  control has a name, a role and, where useful, a description; the whole
  interface can be driven from the keyboard. In detail:

  * Toolbar and panels: Apply, Pause, the file capsule, Find, Main menu,
    Parameters menu, Snapshots, Evaluate line and Clear console are
    announced by name; the file capsule is a real button (Tab,
    Return/Space, VoiceOver "press"); the focus order follows the layout
    left-to-right, top-to-bottom.
  * Menus: the file menu, the main menu, the "+" menu and the "..." menu
    of every card are real menus for VoiceOver. Each entry is announced
    with its state (checked, disabled, submenu) and can be activated; when
    a menu opens the focus is already on the first entry, so it is read at
    once. Keyboard: Up/Down or Tab move, Return activates, Right opens a
    submenu, Left/Esc go back or close; the focus returns to where it was.
  * Code editor: an accessible text area. VoiceOver reads it by character,
    word and line, follows the caret and the selection, and typing,
    selecting and replacing text through the screen reader work like in a
    native text view. The help bar announces the help of the opcode under
    the caret.
  * Parameter cards: sliders, toggles and menus carry the channel name
    ("amp", "amp value"), the Edit and "..." buttons say which channel
    they act on ("Edit amp", "amp menu"), and the fields of the Edit card
    (channel name, Min, Max, Init, Skew, Step, options) are named.
  * XY pad: an accessible control that announces both axes with their
    channel names and values ("X cutoff 0.42, Y res 0.8"). VoiceOver
    increment/decrement moves X; from the keyboard the arrow keys move X
    (left/right) and Y (up/down), Shift for larger steps, Home/End and
    PageUp/PageDown jump to the ends; the pad shows a focus ring.
  * Nothing changes for mouse and touch users: no extra focus rings or
    highlighted menu rows appear unless the keyboard is used.

LIVE CODING

  * Evaluate: Shift+Return (or the right-click menu) sends the selection,
    the instr/opcode block around the caret or the current line to the
    running engine without a full recompile. Orchestra code is merged (an
    existing instr is redefined, notes already playing finish with the old
    version; global code runs at once), lines that start with a score
    statement are sent as real-time events. The sent lines flash.
  * Evaluate line: the help bar turns into an input line (round ">_"
    button at the top right of the console, above the trash button, or
    Cmd+E) for one-liners such as "i 3 0 1" or "gkfb = 0.9", with history
    (Up/Down); Esc goes back to the help bar.
  * Nothing evaluated is saved: at the next Apply only the editor text
    counts (the file stays the reference).

CHANNELS (diagnostics)

  * Main menu > Show Channels (Cmd+4): every channel the engine knows at
    run time - type (k/S/a/f), direction (chnget / chnset), current value
    and who writes it (parameter, host, code, nobody). Channels read by
    the code and written by nobody come first, in yellow: the usual reason
    for "it does not move". "Map" turns one into a parameter (Float, Int,
    Toggle or Menu) with range/default from chn_k hints; indexed families
    (Acc1..Acc16) are one row with "Map 16". Parameters the code only
    writes (GUI indicators like Cabbage LEDs, imported by mistake) are
    flagged "never read by code" with an "Unmap" button that frees the
    slot. Takes the place of the Graphs panel while open.

HOST AND ENGINE

  * 64 Bool (toggle) parameters instead of 32 (176 DAW parameters in all):
    Cabbage step sequencers with 16 steps x On/Hold/Accent no longer lose
    their Play/Stop buttons to the limit. Projects saved with 1.0.4 load
    unchanged (slot indices are the same); in hosts that address
    parameters by index (AU) the 16 Menu parameters move 32 places, so an
    automation lane on a Menu written with 1.0.4 must be re-assigned.
  * Host transport as control channels, same names as Cabbage: HOST_BPM,
    IS_PLAYING, IS_RECORDING, TIME_IN_SECONDS, TIME_IN_SAMPLES,
    HOST_PPQ_POS, HOST_PPQ_BAR_START, TIME_SIG_NUM, TIME_SIG_DENOM -
    updated once per block, no allocation in the audio thread. Standalone:
    HOST_BPM = 120, 4/4.
  * Real-time safety: the audio thread no longer allocates for MIDI (the
    input queue and the midiout buffer are pre-allocated in prepareToPlay)
    and no longer posts messages to the UI when the score ends (an atomic
    flag read by the existing timer). The console path was already
    allocation-free (fixed double buffer).
  * Console warning when the code uses fixed-width I/O opcodes (outs, ins,
    out, outq...) and the track has a different channel count: prefer
    outch / inch, which work with any nchnls.
  * MIDI out test (CSD/Examples/Test/MidiOutTest.csd): notes and CC sent
    to the host, incoming notes echoed - to check the routing in a DAW.

PARAMETERS PANEL

  * Snapshots menu: it stays open - tap a snapshot to recall it (check
    mark on the last one), Save adds the new entry to the list at once, and
    the pencil button on the right of each snapshot (or the right arrow
    key) opens its page with Overwrite, Rename and Delete.
  * XY pad: "; @xy "X" "Y"" in the code shows two Float parameters as one
    two-dimensional pad card (drag, double-click to reset, both still
    separate DAW parameters). Edit shows both channel fields plus the
    range of one axis (Edit X / Edit Y in the "..." menu). Cabbage xypad
    widgets and CsoundQt XY controllers become pads automatically.
  * Monitor: channels written by chnset that are not parameters appear
    read-only in a "Monitor" group at the bottom of the panel - value and
    bar (range from chn_k hints, or the values seen so far), text for
    string channels. The equivalent of CsoundQt / Cabbage meters, displays
    and labels; channels created at run time appear within a second.
    Cabbage GUI messages ("visible(1)", "bounds(...)", identChannels) are
    kept out.
  * Monitor cards: channels "Base1, Base2..." / "Base_1, Base_2..." become
    one card with a bar per channel (spectra, LFO banks, sequencer steps);
    the 11th argument of chn_k adds attributes: "db" (linear amplitude in
    dB), "spark" (sparkline of the last 5 s), "int", "hidden", "group:Name"
    (explicit multi-bar card). See the Guide and MonitorStressTest.csd.
  * Cabbage files get their groups from groupbox / plant containers of the
    GUI, no change to the file needed; "; @group" in the code still wins.
  * Option/Alt + click on a group header opens or closes all groups
    (Monitor included); Expand/Collapse All in the "+" menu include the
    Monitor too. More than 4 groups: only the first starts open when a
    file is loaded; the open/closed state is kept while the set of groups
    does not change.
  * Compact cards: the channel name sits in the title row (no more
    "SLIDER FLOAT" label); toggles and menus are single-line cards; one
    card in edit mode at a time, outlined in the colour of its type.
  * Per-card "..." menu: Copy chnget line, Reset to Init Value, Randomize,
    Show in Code (selects the chnget in the editor), Remove (with
    confirmation). The edit button shows a pencil, and a check mark
    (apply) while the card is in edit mode. "Randomize All" in the "+"
    menu.
  * Live preview: while editing a Float/Int slider the real slider stays
    visible under the name field and follows Min/Max/Init/Skew/Step as
    you type. Inline validation of min/max/init/skew/step, options and
    duplicate channel names.
  * Code <-> panel link: with the caret on a chnget/chnset line the card
    of that channel flashes briefly. A dot flashes next to the name when a
    value is changed from outside (DAW automation, chnset, snapshot
    recall).

GRAPHS AND CONSOLE

  * Graphs: function tables are live - while the panel is open they are
    re-read ~4 times per second and redrawn when their content changes
    (tablew, regenerated ftgen, GEN in a loop): a scope or envelope viewer
    for free, no display opcode needed.
  * Right-click on the help bar: "Copy error" (or "Copy help") puts the
    text shown in the bar on the clipboard.
  * Console: error, warning and "deactivated" lines are never hidden by
    the flood filter (a macro expanded 16 times could bury an INIT ERROR).

EDITOR

  * Csound 7 names looplt / loople / loopgt / loopge and the for ... in
    loop are highlighted and have inline help; the old loop_* entries say
    they were renamed.

IMPORT OF CABBAGE AND CSOUNDQT FILES

  * Cabbage "button" widgets are imported as Bool parameters (they were
    skipped before: Play/Stop/Live/Rec of many examples stayed at 0 and
    the patch seemed silent).
  * When a widget type exceeds its slots, the widgets whose channel the
    code never reads with chnget (LEDs, meters, step indicators) are
    dropped first, so Play/Stop-like buttons later in the file still get
    a slot; the console says how many were skipped.
  * combobox value(n) is 1-based in Cabbage: the default menu entry was
    off by one.
  * One channel = one parameter (a channel used by two widgets, e.g. an
    rslider and an xypad, no longer gives duplicated cards).
  * Examples: the CsoundQt files use chnget / chnset instead of invalue /
    outvalue (their displays and meters show up in Monitor); every example
    uses inch / outch; loop_* renamed for Csound 7; several Cabbage files
    fixed for Csound 7 (delay lines inside UDOs, monitor, pvsadsyn at
    init, HRTF data in SADIR, reinit loops). New tests in CSD/Examples/Test:
    EvaluateTest, HostTransportTest, XYPadTest, MonitorTest,
    MonitorStressTest, MidiOutTest.

DEVELOPMENT

  * Unit tests (juce::UnitTest, Source/Tests/CsoundUnitTests.cpp): parameter
    groups / XY pads parser, Cabbage widget helpers, card field wrapping,
    Csound 7 functional syntax, channel-under-caret, Monitor attributes and
    grouping, channel diagnostics, Cabbage and CsoundQt import, parameter
    snapshots. Run them from Main menu > Config > Run Self-Tests (Debug
    builds, result in the console), with "apeCsound --run-tests"
    (Standalone) or outside the app with scripts/run_unit_tests.sh (the
    pure suites, juce_core only). The pure helpers live in
    CsoundCabbageHelpers.h, CsoundLayoutHelpers.h, CsoundSyntaxHelpers.h,
    CsoundMonitorLayout.h, CsoundChannelDiagnostics.h.

FIXES

  * After Apply the parameter channels could stay at 0 (sliders and menus
    looked reset, chnget returned 0 until the control was touched): the
    new engine was mistaken for the old one when it got the same memory
    address; engines are now told apart by a generation counter.
  * Snapshot names: "Snapshot N" now uses the first free number.
  * The "changed from outside" dot no longer flashes when hovering or
    clicking a toggle.
  * Field rows of the edit card: the last field could disappear at some
    panel widths; the fields now also stretch to the card width.
  * Leaving edit mode no longer shows the old "SLIDER FLOAT" label.
  * Snapshot/Parameter rebuilds no longer need a second click to leave
    edit mode while a field has focus.

1.0.4
-----

Built on Csound 7.0.0, the official release (tag 7.0.0, 21 October 2026). The
previous builds used a develop snapshot; every platform now builds from the
same tagged sources.

ENGINE

  * Csound 7.0.0 linked statically on macOS, iOS, Windows and Linux.
  * OSC opcodes built in (oscinit, osclisten, oscsend, oscbundle, oscraw;
    the uppercase names still work as aliases): liblo and the OSC plugin
    are compiled into the binary and registered on every engine instance.
  * NSLocalNetworkUsageDescription on iOS and macOS: the local-network
    permission for OSC is requested with a proper message.
  * Pause button next to Apply: stops Csound and passes the audio through;
    Apply restarts it.
  * Audio scaling fixed: the output and input are scaled by 0dbfs; a .csd
    with 0dbfs = 32767 is no longer 32767 times too loud.
  * Two-way channels: chnset on a mapped channel moves the parameter
    (slider, host, automation) instead of being overwritten every block.
  * Parameter names and ranges are refreshed in the DAW after Load.
  * Console flood protection: identical messages repeated more than three
    times per second are summarised; the console no longer freezes the
    DAW.
  * Warning in the console when a parameter channel is also used as an
    audio channel (chnget/chnset with a variables), which Csound rejects.

PLUG-IN TYPE

  * The AU / AUv3 is now a Music Effect (aumf): an audio effect that also
    receives MIDI. VST3 stays Fx. One plug-in for every use: to play a
    .csd instrument, load apeCsound as an effect and send it MIDI (the
    Guide explains how in Logic, Ableton Live, Cubase, REAPER, Bitwig,
    Studio One and the iOS hosts). Logic also lists it in the instrument
    slot under "AU MIDI-controlled Effects".

PARAMETERS PANEL

  * Groups: a ; @group Name comment in the code puts the parameters read
    below it - sliders, toggles and menus alike - under one collapsible
    frame; the group of a channel is where its first chnget is; parameters
    without a group go to "Other". Expand All / Collapse All in the +
    menu.
  * Snapshots (camera button on the right of the title bar): named sets of
    parameter values stored in the .csd and in the DAW project. Save,
    Recall, Overwrite, Rename, Delete; saving/renaming/deleting can be
    undone.
  * Larger sliders, with a touch-friendly thumb; on touch screens a
    horizontal drag moves the slider and a vertical one scrolls the panel.
  * Min/max labels shown as floats.

EDITOR

  * Graphs panel docked at the bottom, next to the console: function
    tables and display / dispfft signals drawn in the plug-in instead of
    ASCII graphs in the console; displays always on.
  * Find / Replace bar (magnifier button): match case, whole word, Replace
    / Replace All; Esc closes it.
  * Keyboard shortcuts, the same in the plug-in and in the standalone app:
    Cmd+Return Apply, Cmd+S / Cmd+Shift+S / Cmd+O / Cmd+N, Cmd+F,
    Cmd+1/2/3 panels, Cmd+= / Cmd+-, Cmd+Z / Cmd+Shift+Z, Cmd+/ comment,
    Ctrl+I re-indent, Cmd+[ / ].
  * Undo / Redo move the caret and the selection to the edited text and
    scroll it into view.
  * Block comments /* ... */ keep their colour after edits and scrolling.
  * apeCsound Guide rewritten: full-screen, laid out in sections with
    proper lists; scrolls with wheel, trackpad and finger.
  * The console scrolls with the finger on iOS.

FILES AND SESSIONS

  * Factory examples built into the binary and extracted to CSD/Examples
    on first launch (Cabbage and CsoundQt collections with credits and
    licences in README_Examples.md, plus ape/ and Test/). Open Example...
    and Restore Examples in the file menu.
  * Sessions live in ~/Documents/apeCsound/CSD: CSD/User is the default
    for Save as, CSD/Examples holds the examples.
  * Import Files... on every platform: the dialog shows only the supported
    types and copies each file to the right folder (.csd to CSD/User,
    audio to SSDIR, .udo/.inc/.txt to INCDIR, analysis files to SADIR).
  * Manage Files...: on desktop opens the apeCsound folder in Finder /
    Explorer; on iOS a file manager over the shared folder (import into a
    folder, export to the Files app, delete).
  * iOS file browser for Load / Open Example / Save as, presented like the
    system sheet: the shared App Group folder is not visible in the Files
    app, so apeCsound shows it itself; "Other Locations..." opens the
    system picker.
  * Config > Extra Folders (was "Csound Folders") on every platform: extra
    SSDIR / SADIR / INCDIR folders and the SFDIR output folder; on iOS
    chosen with the system picker and shared by the app and the AUv3.
  * .csd files associated with apeCsound on macOS and iOS (double click /
    Open in).
  * File menu reorganised in groups: Init, Load / Open Example, Save /
    Save as / Reveal in Finder, Import / Manage Files, Restore Examples.

MENUS AND UI

  * Touch-friendly menus on iOS and Android only; desktop keeps the
    native-style popup. Icons on every platform, keyboard shortcuts shown
    on desktop only; wider gap between icon and text.
  * Config menu: Modern Syntax in Help, Follow CSD nchnls, Light Editor,
    Extra Folders.
  * About: engine build line and credits for the examples.

BUILD AND DISTRIBUTION

  * Static Csound build scripts for macOS (universal), iOS (device +
    simulator), Linux and Windows, all pinned to the 7.0.0 tag; the OSC
    plugin is patched to build statically.
  * GitHub Actions for Windows and Linux: VST3 + Standalone, zipped.
  * README rewritten: formats per platform, download links, features,
    build steps.
